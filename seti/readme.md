# Сетевая лаборатория на Ubuntu 24.04 (Vagrant + Ansible)

Данный репозиторий содержит автоматизированный стенд для развертывания многокомпонентной сетевой лаборатории на базе **Ubuntu 24.04 LTS**. Стенд демонстрирует разделение сети на подсети (IP Subnetting), статическую маршрутизацию и настройку трансляции сетевых адресов (NAT/Masquerade).

## Архитектура стенда

Трафик от конечных серверов проходит через каскад роутеров по следующей цепочке:
`centralServer` -> `centralRouter` -> `inetRouter` -> `Интернет (через NAT на хосте)`

## 2. Практическая часть: Реализация

* **Vagrantfile**: Описывает конфигурацию виртуальных машин на базе бокса `bentoubuntu-24.04`, распределяет сетевые адаптеры VirtualBox по внутренним сетям (`virtualbox__intnet`).
* **playbook.yml**: Сценарий Ansible, который динамически генерирует валидные конфигурации **Netplan** для Ubuntu 24.04, управляет метриками дефолтных шлюзов на интерфейсах `eth0` (чтобы пустить трафик по спроектированной схеме), включает `ip_forwarding` и настраивает `iptables MASQUERADE` на `inetRouter`.

---

## 3. Инструкция по запуску

1. Убедитесь, что на хост-системе установлены **Vagrant**, **VirtualBox** и **Ansible**.
2. Клонируйте репозиторий и перейдите в папку проекта.
3. Разверните стенд одной командой (провайдер VirtualBox принудительно зафиксирован):
   ```bash
   vagrant up
   ```
4. Если виртуальные машины уже запущены, но требуется применить или обновить конфигурацию сети:
   ```bash
   vagrant provision
   ```

## 4. Проверка работоспособности стенда

### Тест 1: Сквозной пинг и трассировка с конечного узла
Подключитесь к внутреннему серверу:
```bash
vagrant ssh centralServer
```
Проверьте доступность внешней сети интернет:
```bash
ping -c 4 google.com
```
Выполните трассировку маршрута, чтобы убедиться, что пакеты идут через цепочку роутеров лаборатории, а не напрямую через NAT-интерфейс Vagrant:
```bash
tracepath google.com
```
*Результат:* Пакеты успешно доходят до интернета с 0% потерь. Первый прыжок осуществляется на `centralRouter` (`192.168.0.1`), второй — на стыковочный интерфейс `inetRouter` (`192.168.255.1`).

### Тест 2: Проверка таблиц маршрутизации
На **centralRouter** (`vagrant ssh centralRouter`) команда `ip route show` возвращает статический дефолтный маршрут во внешнюю сеть:
```text
default via 192.168.255.1 dev eth1 proto static
```

На **inetRouter** (`vagrant ssh inetRouter`) команда `ip route show` подтверждает наличие обратного маршрута во внутреннюю сеть:
```text
192.168.0.0/24 via 192.168.255.2 dev eth1
```

### Тест 3: Проверка NAT (Masquerade)
На пограничном шлюзе **inetRouter** правила трансляции адресов успешно обрабатывают и считают пакеты локальной сети:
```bash
sudo iptables -t nat -L POSTROUTING -v -n
```
В выводе присутствует активная цепочка `MASQUERADE` на интерфейсе `eth0`, фиксирующая проходящий трафик.
