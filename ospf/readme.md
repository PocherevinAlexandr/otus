# Домашнее задание: Vagrant-стенд с OSPF

## Цель и текст задания

**Цель:** Создать домашнюю сетевую лабораторию и научиться настраивать динамическую маршрутизацию по протоколу OSPF в Linux-based системах.

**Задачи:**
1. Развернуть 3 виртуальные машины (`router1`, `router2`, `router3`).
2. Объединить их разными изолированными сетями (VLAN).
3. Настроить динамическую маршрутизацию OSPF между машинами (на базе FRRouting — современного преемника Quagga).
4. Изобразить асимметричный роутинг.
5. Сделать один из линков «дорогим», но так, чтобы при этом роутинг оставался симметричным.

**Формат сдачи:** `Vagrantfile` + `Ansible`.

---

## Схема сети (Топология)

Все три маршрутизатора объединены в кольцо тремя транзитными подсетями (`/30`) в единой магистральной области `area 0`. Дополнительно за каждым маршрутизатором настроена своя локальная подсеть (`/24`).

```text
                  [ net1: 192.168.10.0/24 ]
                             | (192.168.10.1)
                         [router1]
                       /           \
       (10.0.12.1)    /             \    (10.0.10.1)
                     /               \
     VLAN r1-r3     /                 \     VLAN r1-r2
   10.0.12.0/30    /                   \   10.0.10.0/30
                  /                     \
       (10.0.12.2)                       (10.0.10.2)
       [router3] ----------------------- [router2]

          |        (10.0.11.1) (10.0.11.2)        |
          |          VLAN r2-r3: 10.0.11.0/30     |
  (192.168.30.1)                          (192.168.20.1)

          |                                       |
[ net3: 192.168.30.0/24 ]               [ net2: 192.168.20.0/24 ]
```

* **Сеть управления (Management):** `192.168.56.10`–`12` (используется Ansible для подключения и настройки хостов).

## Особенности проектирования и реализации

* **Стек и окружение:** Вместо устаревшего пакета Quagga используется **FRRouting (FRR)** на базе **Ubuntu 24.04 (`bentoubuntu-24.04`)** в VirtualBox.
* **Автоопределение интерфейсов:** В Jinja2-шаблоне `ansible/templates/frr.conf.j2` имена сетевых интерфейсов определяются автоматически по их IP-адресам из фактов Ansible, что исключает привязку к конкретным именам устройств (`eth1` / `enp0s8`).
* **Поддержка асимметричного трафика:** На всех узлах отключена проверка обратного пути ядра Linux (`net.ipv4.conf.all.rp_filter=0` и `net.ipv4.conf.default.rp_filter=0`), чтобы ядро не отбрасывало пакеты, приходящие и уходящие через разные интерфейсы.
* **Управление режимами маршрутизации:** Переключение между асимметричным и симметричным роутингом вынесено в переменную `symmetric_routing` в файле `ansible/defaults/main.yml` и применяется точечно по тегу `setup_ospf`.

## Инструкция по запуску и проверке

### 1. Развертывание стенда
Из корневого каталога проекта выполните:
```bash
vagrant up
```
По умолчанию в `ansible/defaults/main.yml` установлено значение `symmetric_routing: false`. На прямом линке `router1 -> router2` (`10.0.10.1`) задана высокая стоимость `ip ospf cost 1000`, а на обратном интерфейсе `router2 -> router1` (`10.0.10.2`) оставлена стандартная стоимость.

### 2. Проверка асимметричного роутинга
1. На `router1` запустите пинг между локальными сетями:
   ```bash
   ping -I 192.168.10.1 192.168.20.1
   ```
2. На `router2` с помощью `tcpdump` фиксируется разделение потоков:
   * На интерфейсе `eth2` (в сторону `router3`) приходят только запросы `ICMP echo request`.
   * На интерфейсе `eth1` (напрямую к `router1`) уходят только ответы `ICMP echo reply`.

### 3. Переключение на симметричный роутинг при «дорогом» линке
1. В файле `ansible/defaults/main.yml` измените параметр на:
   ```yaml
   symmetric_routing: true
   ```
2. Примените изменения с помощью Ansible-тега (файл `ansible.cfg` размещен в корне проекта):
   ```bash
   ansible-playbook -i ansible/hosts -l all ansible/provision.yml -t setup_ospf
   ```
3. **Результат проверки (`tcpdump` на `router2`):**
   * `sudo tcpdump -i eth1 icmp` — **0 пакетов** (прямой линк между `router1` и `router2` теперь имеет стоимость `1000` в обе стороны и не используется).
   * `sudo tcpdump -i eth2 icmp` — через интерфейс в сторону `router3` симметрично проходят как `ICMP echo request`, так и `ICMP echo reply`.
