# Стенд автоматического резервного копирования на базе BorgBackup

Данный проект реализует отказоустойчивую архитектуру автоматического резервного копирования каталога `/etc` с клиентской машины на удаленный специализированный сервер бэкапов. Развертывание и настройка стенда полностью автоматизированы с помощью Vagrant и Ansible.

## 1. Описание архитектуры стенда

Стенд состоит из двух виртуальных машин под управлением Ubuntu 24.04 LTS:

*   **backup (192.168.56.160):** Выделенный сервер резервных копий.
    *   В конфигурации подключен дополнительный жесткий диск размером 2 ГБ.
    *   Диск размечен, отформатирован в файловую систему `ext4` и смонтирован в точку `/var/backup`.
    *   Создан выделенный служебный пользователь `borg`. В целях безопасности вход по паролю для него заблокирован, авторизация выполняется строго по SSH-ключам.
    *   Репозиторий Борга инициализирован в чистой подпапке `/var/backup/repo`, что исключает конфликты со служебной директорией `lost+found`.
*   **client (192.168.56.150):** Целевой сервер (источник бэкапов).
    *   Для суперпользователя `root` сгенерирована SSH-ключевая пара. Публичный ключ автоматически проброшен на сервер в `authorized_keys` пользователя `borg`.
    *   Настроен системный таймер и служба `systemd` для выполнения регулярных бэкапов без использования сторонних планировщиков.

---

## 2. Логика процесса бэкапа и автоматизация

Резервное копирование выполняется полностью в автоматическом режиме на стороне клиента:

1.  **Периодичность:** Системный таймер `borg-backup.timer` запускает службу бэкапа **каждые 5 минут**.
2.  **Именование архивов:** Каждая резервная копия получает уникальное имя, содержащее метку времени запуска с точностью до секунд (формат: `etc-YYYY-MM-DD_HH:MM:SS`).
3.  **Логирование:** Весь вывод процесса (`stdout` и `stderr`) перенаправляется утилитой `logger` в системный журнал `syslog` с уникальным тегом `borg-backup`. Логи содержат детальную статистику оригинального, сжатого и дедуплицированного размера архивов.
4.  **Политика удержания (Ротация):** После каждого успешного создания бэкапа автоматически запускается утилита `borg prune`. Настроена глубина хранения:
    *   `--keep-daily=90` (сохранять по одной копии на конец дня за последние 3 месяца).
    *   `--keep-monthly=12` (хранить ежемесячные срезы за год).
    *   `--keep-yearly=1` (хранить один годовой архив).
    *   *Примечание:* Из-за действия политики внутри одного дня сохраняется только самая первая и самая свежая копия, промежуточные пятиминутные бэкапы ротируются для экономии диска.

---

## 3. Инструкция по проверке и тестированию стенда

### Шаг 1. Развертывание стенда
Выполните на хост-машине чистый запуск окружения:
```bash
vagrant destroy -f
vagrant up
```
*Vagrant создаст машины, а встроенный Ansible-плейбук полностью настроит диски, ключи, репозиторий и запустит первый автоматический бэкап.*

### Шаг 2. Проверка статуса автоматики и просмотр логов
Зайдите на клиентскую машину под `root`:
```bash
vagrant ssh client
sudo -i
```
Проверьте, что фоновый таймер активен:
```bash
systemctl status borg-backup.timer
```
Просмотрите логи создания бэкапов и статистику дедупликации в системном журнале:
```bash
journalctl -t borg-backup --no-pager -n 50
```

### Шаг 3. Ручной просмотр репозитория бэкапов
Чтобы увидеть список физически созданных архивов на сервере:
```bash

borg list borg@192.168.56.160:/var/backup/repo
```
Запросит парольную фразу "Otus1234"

## 4. Инструкция по восстановлению данных при аварии

В соответствии с заданием, для демонстрации процесса восстановления и исключения поломки живой операционной системы, извлечение файлов выполняется в выделенную тестовую директорию.

### Шаг 1. Остановка автоматики на время работ
Чтобы фоновые процессы не блокировали репозиторий, временно остановите таймер:
```bash
systemctl stop borg-backup.timer
```

### Шаг 2. Имитация повреждения данных
Создайте чистую директорию, имитирующую точку восстановления:
```bash
mkdir -p /tmp/recovery_test
cd /tmp/recovery_test
```

### Шаг 3. Извлечение файлов из архива
Выберите имя нужного архива из списка `borg list` и запустите восстановление каталога `etc`:

```bash
# Пример команды с указанием конкретного имени архива
borg extract --progress borg@192.168.56.160:/var/backup/repo::etc-2026-10-28_08:01:18 etc
```

### Шаг 4. Проверка целостности восстановленных данных
Проверьте, что структура каталогов и конфигурационные файлы успешно извлечены из бэкапа сервера:
```bash
ls -la /tmp/recovery_test/etc
cat /tmp/recovery_test/etc/hostname
```

После завершения проверок верните систему в штатный режим работы:
```bash
systemctl start borg-backup.timer
```
